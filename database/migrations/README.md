# SQLマイグレーション

マイグレーションSQLは、このディレクトリへ`YYYYMMDDHHMMSS_description.sql`形式で追加します。現在のテーブルの一覧は[README](../../README.md#データベースとマイグレーション)を参照してください。

- ファイル名の昇順で未適用のSQLを実行します。
- 適用済みファイル名は`schema_migrations`テーブルへ記録します。
- 1ファイルには1つのスキーマ変更を記載します。
- 適用済みファイルは変更せず、新しいファイルで追加変更します。
- 本番データ、ダンプ、個人情報、秘密情報を含めません。
- **1リリース分の変更は、直前のリリースのコードがそのまま動作し続けられる範囲にとどめます（additive-only）。** 本番デプロイは新リリースを完成させてから公開先を切り替え、コード側の問題が判明したときは公開先を直前のリリースへ戻します（README「本番デプロイ」）。マイグレーションにロールバックは無いため、列・テーブルの削除やNOT NULL化・リネームなど、旧リリースのコードを壊す変更は、それを使わなくなったリリースが十分に定着してから、別リリースで段階的に行います。
- 将来必要になりそうなテーブルを先回りして追加しません。
- 動作確認だけを目的としたテーブルを追加しません。マイグレーション機構の検証は`tests/Integration/MigrationRunnerTest.php`が一時マイグレーションで行います。
